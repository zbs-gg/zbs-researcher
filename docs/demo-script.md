# ZBS Researcher — demo-video script (2–3 мин)

Shot list для демо-видео. Цель: зритель за ≤3 минуты понимает, что это,
почему это лучше «нормального ресёрчера», и ставит одной командой.

**Единственный prerequisite: Node.js ≥ 18** — для npx-однострочника
(нативный путь — две команды `claude plugin …` — обходится вообще без
node). Claude Code у зрителя, понятно, уже стоит: это демо его плагина.

---

## Shot list

| # | Шот | Тайминг | Длит. |
|---|---|---|---|
| 1 | Hook (talking head / текст на экране) | 0:00–0:15 | 15s |
| 2 | npx-инсталл в живом терминале | 0:15–0:45 | 30s |
| 3 | Claude Code: первый вопрос визарда (питч персоны) | 0:45–1:05 | 20s |
| 4 | ОТДЕЛЬНЫЙ терминальный шот: анимированный борд | 1:05–1:35 | 30s |
| 5 | brief.html — скролл отчёта | 1:35–2:05 | 30s |
| 6 | Персона-вопросы (род/тон → zbs) + synthesis в zbs-тоне | 2:05–2:35 | 30s |
| 7 | Tiers glance + CTA | 2:35–2:55 | 20s |

**Итого: 2:55.**

### Shot 1 — Hook (0:00–0:15)

Talking head или текст на чёрном.

Реплика:

> «Ресёрчеров нормальных нет — некоторые из этого строят целые компании.
> Я потратил два часа.»

Дальше без паузы — hard cut в терминал.

### Shot 2 — npx install (0:15–0:45)

Живой терминал, ≥80 колонок, крупный шрифт.

```bash
npx -y zbs-researcher@latest
```

Инсталлер печатает баннер и **две команды, которые собирается выполнить**,
и ждёт подтверждения. Это планируемый бит, не заминка:

- Пауза на confirm-промпте. Реплика: «Смотрите — он спрашивает разрешение.
  Вежливый.» → Enter.
- Спиннер, `claude plugin list` проходит, next steps на экране.

Примечание: `-y` в команде — это флаг npx (skip package-install prompt),
сам инсталлер остаётся интерактивным — что нам и нужно для этого бита.
Полностью тихий вариант (`npx -y zbs-researcher@latest --yes`) в кадре не
используем.

### Shot 3 — Claude Code: первый вопрос визарда (0:45–1:05)

Запись или скрин Claude Code в свежем проекте. Сказать:

```text
запусти deep research
```

В кадре — ПЕРВЫЙ вопрос визарда: ZBS Researcher представляется по имени
(«Привет — я ZBS Researcher…», $0 и ноль ключей — прямо в тексте вопроса)
с опциями Auto / Manual / Skip. Выбрать **Auto**, назвать тему (тема — из
Shot 5, см. варианты там).

### Shot 4 — ОТДЕЛЬНЫЙ терминальный шот: анимированный борд (1:05–1:35)

Прямой запуск раннера в живом TTY (≥80 колонок):

```bash
python3 "$SKILL_DIR/scripts/deep-research.py" "<та же тема>" \
    --only hackernews,hiring,polymarket,github,github-issues,reddit,bluesky \
    --max-items 5
```

(`$SKILL_DIR` — абсолютный путь к установленному скиллу; визард сам отдаёт
эту команду в готовом для вставки виде после Tier-0 брифа.)

В кадре: баннер ZBS RESEARCHER + живой борд — спиннеры по каналам,
статусы OK/items, elapsed, финальный footer.

**Честная механика съёмки (важно):** в агентском пути (Shot 3) борд **по
дизайну не рендерится** — там stderr не TTY, и раннер печатает plain-строки.
Анимация живёт только в прямом терминальном запуске. Поэтому это отдельное
окно/отдельный дубль: либо два окна рядом, либо склейка монтажом. В
войсовере честно: «а вот так прогон выглядит, если запустить его прямо в
терминале».

### Shot 5 — brief.html (1:35–2:05)

Плавный скролл готового `brief.html` в браузере (тёмная тема). Прогон по
теме сделать ЗАРАНЕЕ, чтобы бриф был жирный.

Кандидаты тем (CIS-ниша, живой сигнал в бесплатных каналах) — выбрать одну:

1. **«Монетизация Telegram Mini Apps»** — Telegram-first аудитория, живые
   репы на GitHub, треды на HN/Reddit.
2. **«Приём платежей за цифровые продукты из СНГ без Stripe»** — Paddle /
   Lemon Squeezy / крипта; болит у половины аудитории, тонны живых тредов.
3. **«AI-клоны голоса для инфопродуктов»** — ElevenLabs vs опенсорс,
   GitHub velocity + реальные реакции на Reddit.

Войсовер: план → каналы → противоречия → выводы; «это не саммари выдачи —
это реакции живых людей и цифры, которые LLM не выдумает».

### Shot 6 — персона-вопросы + zbs-тон (2:05–2:35)

Снова Claude Code: визард (после брифа) задаёт свои **два** вопроса одним
экраном — род («она / он / нейтрально») и тон («деловой / zbs /
нейтральный / свой»). Выбрать род на вкус, тон — **zbs**.

Затем в кадре — кусок synthesis, озвученный в zbs-тоне, в духе:

> «7 каналов, ноль воды — и тут есть жир. Три находки, погнали.»

Войсовер: «тон меняет только подачу — находки, ранжирование и предупреждения
не трогает».

### Shot 7 — tiers glance + CTA (2:35–2:55)

Экран с тир-глансом (секция «Тиры — коротко» из README): Tier 0 бесплатно /
Tier 1 свои ключи / Tier 2 один OpenRouter / opt-in Telegram·TikTok·Threads·
Meta Ads. Реплика: «всё, что вы видели — Tier 0, ноль ключей».

Финальный кадр — CTA крупно:

```bash
npx -y zbs-researcher@latest
```

и ссылка `github.com/zbs-gg/zbs-research`.

## Ordering reconciliation — где creative license, а где реальный флоу

Реальный флоу спрашивает персону **ПОСЛЕ** Tier-0 брифа (R2); видео сжимает
арку — этот script явно помечает, где creative license vs реальный порядок,
чтобы демо не врало про механику онбординга.

Реальный порядок онбординга: STEP 1 (питч внутри первого вопроса) → STEP 2
(Tier-0 прогон + бриф, до любых вопросов про ключи) → предложение живого
борда для своего терминала → STEP 2.5 (персона: род + тон) → STEP 3 (тиры,
по одному).

- **Shots 2 → 3 → 5 → 6 → 7 идут в реальном порядке** — инсталл, первый
  вопрос, бриф, персона-вопросы после брифа, тиры. Тут license нет.
- **Shot 4 — creative license по механике, не по порядку:** прогон в
  агентском пути реально происходит между Shot 3 и Shot 5, но борд там не
  рендерится (не TTY — plain-строки по дизайну). Анимация снимается
  отдельным терминальным дублем и вставляется в этот момент арки. Войсовер
  проговаривает это честно («если запустить прямо в терминале»).
- **Shot 6, кусок synthesis в zbs-тоне — creative license (склейка):** тон
  применяется к ответам ПОСЛЕ выбора; показанный zbs-фрагмент — это
  пере-озвученный вывод того же прогона (попросить агента переозвучить
  summary после выбора тона — это ровно то, что механика и делает), а не
  «бриф из Shot 5 был в zbs с самого начала».
- Везде остальное показанное — реальная механика без постановки: confirm у
  инсталлера, $0/ноль ключей в первом вопросе, два персона-вопроса одним
  экраном, plain-вывод в агентском пути.

## Pre-production чеклист

- [ ] Node ≥ 18 стоит; `claude` CLI логинен.
- [ ] Прогон по выбранной теме сделан заранее — `brief.html` готов и жирный.
- [ ] Терминал: ≥80 колонок, крупный шрифт, тёмная тема; `NO_COLOR` НЕ
      выставлен, `TERM` не `dumb`.
- [ ] Ключи не нужны и не в кадре: весь демо-путь — Tier 0.
- [ ] Свежий проект для Claude Code-шотов: `onboarding.json` отсутствует
      (иначе визард молча пропустит онбординг — `wizard_done`).
- [ ] npx-кэш прогрет или `@latest` явно в команде (стейл-кэш npx — известная
      гоча).
